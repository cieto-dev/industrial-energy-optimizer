# Technologies

```text
knowledge-base/
└── technologies/
    ├── biomass.json
    ├── electrification.json
    ├── heat_pump.json
    ├── solar_thermal.json
    ├── thermal_storage.json
    └── waste_heat_recovery.json
```

The purpose of this folder is to store the **technical specifications, capabilities, and operational characteristics** of every clean-energy technology supported by the optimizer.

Instead of hardcoding technology properties into Python, the backend loads the appropriate JSON file whenever it evaluates a transition pathway.

---

# Why is this folder needed?

Suppose the optimizer wants to evaluate an **Electric Boiler**.

It needs to know:

* Maximum operating temperature
* Efficiency
* Typical installation cost
* Suitable industries
* Required infrastructure
* Advantages
* Limitations

Rather than storing all this information in code, it simply loads:

```text
technologies/electrification.json
```

Every technology follows the same approach.

# Recommended JSON Structure

Every technology file should have a similar structure.

Example:

```json
{
    "technology": "Electric Boiler",

    "temperature_range": {
        "min": 100,
        "max": 1000
    },

    "efficiency": 0.95,

    "suitable_industries": [
        "Textile",
        "Food Processing",
        "Pharma"
    ],

    "required_inputs": [
        "Electricity"
    ],

    "advantages": [
        "High efficiency",
        "Zero on-site emissions"
    ],

    "limitations": [
        "Requires sufficient grid capacity"
    ]
}
```

Having a consistent schema makes it easy for the optimizer to process every technology in the same way.

# Why separate every technology into its own JSON file?

Instead of writing code like:

```python
if technology == "Heat Pump":
    ...
elif technology == "Solar Thermal":
    ...
elif technology == "Biomass":
    ...
```

the backend follows a data-driven approach:

```python
technology = load_json("technologies/heat_pump.json")

evaluate(technology)
```

This offers several advantages:

* New technologies can be added by simply creating another JSON file.
* Existing technology specifications can be updated without changing the application logic.
* All technology profiles follow a consistent structure, making the optimizer scalable and easier to maintain.

# Role of the `technologies` folder in your project

The `knowledge-base/technologies` folder serves as the **technical knowledge repository** of the Industrial Energy Transition Optimizer. Each JSON file defines the engineering characteristics of a specific decarbonization technology, including its operating temperature, efficiency, infrastructure requirements, industry compatibility, and limitations. During optimization, the backend loads these technology profiles, validates them against the constraint engine, estimates their financial and environmental impact, and finally ranks the feasible pathways. This modular design keeps engineering knowledge separate from the optimization algorithms, making the system extensible, maintainable, and capable of supporting additional technologies in future versions.
