Perfect. This folder is **not a calculation module** like `models/`, nor is it part of the request handling like `backend/`. Instead, the **`knowledge-base/emissions/`** folder is the project's **reference data repository** for emission-related information.

The `emission.py` model performs emission calculations, but **it should not hardcode emission values**. Instead, it reads standardized emission factors from this folder. This separation keeps the calculation logic independent from the reference data, making updates easier and more reliable.

# knowledge-base/emissions/

## Purpose

The `emissions` folder stores all validated emission-related reference data used by the Industrial Energy Transition Optimizer.

Rather than embedding emission coefficients directly inside the source code, the application loads them from structured JSON files stored in this directory.

This design makes the system:

* maintainable
* transparent
* easy to update
* easier to validate against official data sources

---

```text
knowledge-base/

```

# 1. emission_factors.json

## Responsibility

This file stores the emission factors associated with different fuels and energy sources.

Each factor represents the amount of greenhouse gas emitted per unit of fuel or energy consumed.

Typical entries may include:

* Coal
* Biomass
* Natural Gas
* Diesel
* LPG

---

### Example Structure

```json
{
    "coal": {
        "emission_factor": 2.42,
        "unit": "kg CO₂/kg"
    },
    "diesel": {
        "emission_factor": 2.68,
        "unit": "kg CO₂/L"
    }
}
```

*(Illustrative structure for explanation.)*

---

### How it is used

When the emission model receives

```text
Coal Consumption = 1500 kg/day
```

it retrieves the corresponding emission factor from

```text
emission_factors.json
```

and computes

```text
CO₂ Emissions
```

without hardcoding any numerical values inside the program.

---

### Why separate it?

Suppose updated government guidelines publish new emission factors.

Only

```text
emission_factors.json
```

needs to be updated.

The emission calculation code remains unchanged.

---

# 2. grid_factors.json

## Responsibility

This file stores emission factors associated with electricity supplied by the power grid.

Grid electricity is not emission-free; its carbon intensity depends on how electricity is generated.

The emission model uses this file whenever electricity consumption contributes to the factory's emissions.

---

### Example Structure

```json
{
    "grid": {
        "emission_factor": 0.72,
        "unit": "kg CO₂/kWh"
    }
}
```

*(Illustrative structure for explanation.)*

---

### Example Flow

Factory

```text
Electricity Usage

4500 kWh/day
```

↓

Read

```text
grid_factors.json
```

↓

Calculate

```text
Grid CO₂ Emissions
```

---

### Why is this separate?

Fuel emission factors and electricity emission factors originate from different datasets and may change independently.

Keeping them in separate files improves organization and simplifies updates.

# 3. EmissionsSummary.txt

## Responsibility

This document provides a human-readable summary of the emission datasets used in the application.

Instead of containing machine-readable values, it typically serves as documentation describing:

* available emission datasets
* data sources
* assumptions
* units of measurement
* version information
* notes for developers

---

### Purpose

It helps developers understand

* where emission values originate,
* what assumptions were used,
* and how the JSON files should be interpreted.

Unlike the JSON files, this document is intended for **documentation rather than computation**.

# Why use JSON instead of hardcoding?

Using JSON files provides several architectural benefits:

* **Maintainability:** Emission values can be updated without modifying source code.
* **Transparency:** Reference values remain visible and auditable.
* **Extensibility:** New fuels or energy sources can be added without changing the emission logic.
* **Consistency:** All modules use the same standardized emission factors.
* **Validation:** Values can be traced back to documented assumptions and reference sources.

| --------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **`emission_factors.json`** | Stores emission factors for fuels such as coal, biomass, diesel, and other energy sources used in emission calculations. |
| **`grid_factors.json`**     | Stores emission factors for grid electricity used to estimate emissions from electrical energy consumption.              |
| **`EmissionsSummary.txt`**  | Documents the emission datasets, assumptions, units, and reference information for developers.                           |

## Why this folder exists

The **`knowledge-base/emissions/`** folder serves as the **authoritative source of emission reference data** for the project. It separates **data** from **calculation logic**, allowing the `emission.py` model to perform consistent and transparent emission calculations using externally maintained reference values. This design improves maintainability, traceability, and makes future updates to emission factors straightforward without affecting the core software architecture.
