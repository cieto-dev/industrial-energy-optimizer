Excellent. This is the **Finance Knowledge Base**, which provides all the economic data required by the optimizer. The engineering modules determine **what is technically possible**, while this folder answers **whether the solution is financially viable**.

# Finance

```text
knowledge-base/
└── finance/
    ├── electricity_tariffs.json
    ├── fuel_prices.json
    ├── subsidies.json
    └── technology_costs.json
```

This folder stores all the financial parameters used by the system.

It provides answers to questions such as:

* What is the price of electricity?
* What is the current cost of coal or biomass?
* How much does an electric boiler cost?
* Is any government subsidy available?

Instead of embedding these values in the program, the optimizer loads them from JSON files. This allows financial data to be updated independently without modifying the calculation logic.

---

# Why is this folder needed?

Once a technology passes the **Constraint Engine**, the system must evaluate its economic feasibility.

The finance module calculates:

```text
Technology Cost
        │
        ▼
Operating Cost
        │
        ▼
Annual Savings
        │
        ▼
Payback Period
        │
        ▼
Financial Ranking
```

All these calculations rely on the JSON files inside the `finance` folder.

---

# 1. electricity_tariffs.json

## Purpose

Stores the cost of electricity used in financial calculations.

Electricity prices vary by:

* State
* Consumer category
* Industrial tariff slab

Rather than assuming one fixed value, the optimizer reads the tariff from this file.

Example

```json
{
    "Punjab": {
        "industrial": 7.8
    },

    "Maharashtra": {
        "industrial": 8.3
    }
}
```

(Unit: ₹/kWh)

---

### Example Calculation

Factory electricity consumption

```text
4000 kWh/day
```

Electricity tariff

```text
₹8/kWh
```

Daily electricity cost

```text
4000 × 8

= ₹32,000/day
```

This value contributes to the operating cost of the selected pathway.

---

# 2. fuel_prices.json

## Purpose

Stores market prices of fuels used in industrial processes.

Example fuels:

* Coal
* Biomass
* Diesel
* Natural Gas

Example structure

```json
{
    "coal": {
        "price_per_kg": 9
    },

    "biomass": {
        "price_per_kg": 5
    },

    "diesel": {
        "price_per_liter": 92
    }
}
```

---

### Example Calculation

Factory consumes

```text
Coal = 2000 kg/day
```

Coal price

```text
₹9/kg
```

Daily fuel cost

```text
2000 × 9

= ₹18,000/day
```

If the factory switches to biomass, the optimizer repeats the calculation using the biomass price and compares the operating costs.

---

# 3. technology_costs.json

## Purpose

Stores the installation (CapEx) cost of each technology.

The optimizer needs this information to calculate:

* Capital investment
* Total project cost
* Return on Investment (ROI)
* Payback period

Example

```json
{
    "electric_boiler": {
        "capex": 2800000
    },

    "biomass_boiler": {
        "capex": 3500000
    },

    "heat_pump": {
        "capex": 4500000
    }
}
```

---

### Example Calculation

Technology selected

```text
Electric Boiler
```

CapEx

```text
₹28 lakh
```

Annual savings

```text
₹7 lakh
```

Payback

```text
28 ÷ 7

= 4 years
```

Without this file, the system cannot estimate the investment required or the financial return.

---

# 4. subsidies.json

## Purpose

Stores available government incentives or subsidies that reduce the effective project cost.

These may include:

* Central government schemes
* State government subsidies
* MSME incentives
* Renewable energy support

Example

```json
{
    "electric_boiler": {
        "subsidy_percent": 20
    },

    "solar_thermal": {
        "subsidy_percent": 30
    }
}
```

---

### Example Calculation

Electric Boiler Cost

```text
₹30 lakh
```

Subsidy

```text
20%
```

Effective investment

```text
₹30 lakh

−

20%

=

₹24 lakh
```

The optimizer then uses ₹24 lakh—not ₹30 lakh—for financial calculations.

# How these files work together

Suppose the optimizer recommends an **Electric Boiler**.

The finance module performs the following sequence:

### Step 1 – Read installation cost

```text
technology_costs.json

↓

CapEx = ₹28 lakh
```

---

### Step 2 – Read electricity tariff

```text
electricity_tariffs.json

↓

Operating Cost = ₹32,000/day
```

---

### Step 3 – Compare with current fuel cost

```text
fuel_prices.json

↓

Current Coal Cost = ₹18,000/day

↓

New Electricity Cost = ₹32,000/day
```

---

### Step 4 – Apply subsidy

```text
subsidies.json

↓

20% subsidy

↓

Effective CapEx = ₹22.4 lakh
```

---

### Step 5 – Financial Analysis

The optimizer calculates:

```text
CapEx

↓

Operating Cost

↓

Annual Savings

↓

Payback Period

↓

Financial Score
```

These outputs are then sent to the **Finance & Impact Layer**, which computes metrics such as annual operating cost, savings, and payback before the optimizer ranks the feasible pathways. This matches the architecture where financial analysis is performed after technical feasibility has been established.

# Why keep financial data in JSON?

Instead of writing:

```python
electricity_price = 8

coal_price = 9
```

the system loads them dynamically:

```python
tariff = electricity_tariffs[state]["industrial"]

coal_price = fuel_prices["coal"]["price_per_kg"]

capex = technology_costs["electric_boiler"]["capex"]
```

This design separates **financial data** from **business logic**, making the application easier to maintain. If electricity tariffs, fuel prices, or subsidy schemes change, only the corresponding JSON files need updating.

# Role of the `finance` folder in your project

The `knowledge-base/finance` folder acts as the **economic reference library** of the Industrial Energy Transition Optimizer. It stores all monetary parameters—energy tariffs, fuel prices, technology installation costs, and subsidies—that are required to evaluate the financial viability of each transition pathway. By centralizing this information in JSON files, the optimizer can calculate operating costs, capital investment, annual savings, and payback periods while keeping financial data independent from the core optimization algorithms.
