# Industrial Energy Transition Optimizer — Bibliography & Reference Material

This bibliography is the human-readable reference index for the research material used to develop the Industrial Energy Transition Optimizer knowledge base and datasets.

The canonical machine-readable source registry is:

`knowledge-base/references/sources.json`

All knowledge-base provenance should resolve through the corresponding `source_id` in that registry. This document is a presentation layer only and must not be treated as a second source registry.

## Provenance and Maintenance

- Canonical source registry: `knowledge-base/references/sources.json`
- Compatibility citation index: `knowledge-base/references/citations.json`
- Research bibliography: `research/bibliography.md`
- Repository: `cieto-dev/industrial-energy-optimizer`
- Source registry size: 56 canonical source IDs
- `source_id` values must remain stable across knowledge-base datasets, policies, technologies, finance records, constraints, emissions data, and future application consumers.
- Source metadata should be changed in `sources.json`; this bibliography should be regenerated from that registry rather than maintained independently.
- A `null` URL indicates that the source is an internal project assumption/derived project reference for which no external publication URL is registered. It must not be replaced with an invented URL.

## 8. Reference Integrity Rules

The following rules apply to this bibliography and the canonical source registry:

1. `source_id` is the stable provenance identifier.
2. Every source used by the knowledge base should resolve to exactly one entry in `knowledge-base/references/sources.json`.
3. `sources.json` is the authoritative source of title, organization, year, and URL metadata.
4. `citations.json` must not become a second source database.
5. This bibliography must not introduce source records that are absent from `sources.json`.
6. URLs shown here must match the canonical registry.
7. Internal sources may legitimately have no external URL.
8. Source IDs must not be renamed merely for formatting or readability.
9. If a source is replaced by a newer authoritative document, the registry and all dependent knowledge-base records must be updated together.
10. Any future source addition must first be registered in `sources.json` before being referenced by a knowledge-base record.
