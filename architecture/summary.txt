Perfect—that folder is your **software architecture documentation**. These `.drawio` files are diagrams created with **draw.io (diagrams.net)**. They explain how your system works before you write the code.

For your SIH project, here's what each file usually represents:

### 1. `system_architecture.drawio` ⭐ (Start here)

This is the **big picture** of the entire project.

It answers:

* What components does the system have?
* How do they communicate?

Example:

```text
              User
                │
                ▼
        Streamlit Frontend
                │
                ▼
        FastAPI Backend
        ┌───────┴────────┐
        ▼                ▼
 Optimization      Database
        │                │
        └───────┬────────┘
                ▼
      Recommendation Engine
                │
                ▼
           Results Dashboard
```

Think of it as the map of your whole application.

# Relating this to your SIH project

From your project's architecture, the system follows this pipeline: user input → application layer → baseline model → technology models → constraint engine → scenario generator → optimizer → finance & impact → recommendation dashboard. 

So your diagrams likely correspond to:

| File                         | What it shows                                  |
| ---------------------------- | ---------------------------------------------- |
| `system_architecture.drawio` | Entire project architecture                    |
| `data_flow.drawio`           | Movement of factory data through the optimizer |
| `database_er.drawio`         | SQLite/PostgreSQL schema                       |
| `decision_flow.drawio`       | Logic for selecting technologies               |
| `api_flow.drawio`            | Frontend ↔ Backend communication               |
| `deployment.drawio`          | How the application is hosted                  |

### My suggestion

Open and complete them in this order:

1. ✅ `system_architecture.drawio`
2. ✅ `data_flow.drawio`
3. ✅ `decision_flow.drawio`
4. ✅ `api_flow.drawio`
5. ✅ `database_er.drawio`
6. ✅ `deployment.drawio`

That order makes the design process much easier because each diagram builds on the previous one.
