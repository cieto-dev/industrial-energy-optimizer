# Folder: `reports/`

```
reports/
│
├── excel_report.py
├── pdf_report.py
└── report_generator.py
```

This folder is responsible for **turning the optimizer's results into documents that humans can read, share, print, or submit**.

Think of it as the **presentation layer for files**.

The engineering modules calculate answers.

The reports module explains those answers.

According to your SIH architecture, this belongs near the final stages of the pipeline after optimization, finance, and recommendation generation, where results are prepared for dashboards and exports.

# Why separate reports from the optimizer?

Imagine if the optimizer itself generated PDFs.

Soon the optimizer becomes filled with things like

* page margins
* fonts
* tables
* Excel formatting
* logos

instead of optimization.

That is terrible software architecture.

Instead:

```
Optimizer
      │
      ▼
Produces clean data

↓

Reports folder

↓

Produces documents
```

This follows the **Single Responsibility Principle**.

Every module has one job.

# Business Logic Behind the Folder

The reports folder is **not responsible for making decisions**. Its responsibility is to **present the decisions already made**.

For example:

* The optimizer decides that a biomass boiler is the best option.
* The finance module calculates the payback period.
* The impact module estimates CO₂ reduction.
* The reports module packages all of this into documents suitable for different audiences.

This separation aligns with the architecture described in your SIH master document, where calculation modules produce recommendations first, and the dashboard/reporting layer presents those results to users.

# Summary Table

| File                  | Purpose                                                 | Inputs                                                   | Outputs                                 | Dependencies                                                    |
| --------------------- | ------------------------------------------------------- | -------------------------------------------------------- | --------------------------------------- | --------------------------------------------------------------- |
| `report_generator.py` | Coordinates report creation and acts as the entry point | Final recommendation object, report type, export options | PDF and/or Excel files (or their paths) | Calls `pdf_report.py`, `excel_report.py`; invoked by the UI/API |
| `pdf_report.py`       | Produces a formatted, printable PDF report              | Structured recommendation data                           | `.pdf` document                         | PDF generation library, charts/assets if needed                 |
| `excel_report.py`     | Produces an editable Excel workbook                     | Structured recommendation data                           | `.xlsx` workbook                        | Excel library (e.g., openpyxl/xlsxwriter), formatting utilities |

### Folder Dependencies (High-Level)

| Receives Data From                                 | Sends Output To                                       |
| -------------------------------------------------- | ----------------------------------------------------- |
| Optimization engine, Finance module, Impact module | User download, Dashboard, Email service, File storage |

This folder is an example of a **reporting layer**: it converts structured business results into human-readable artifacts without performing engineering or financial calculations itself.
