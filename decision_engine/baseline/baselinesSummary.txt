## What is a Baseline?

A **baseline** is simply the **current state of the factory before any improvements**.

Imagine you're a consultant visiting a factory. Before recommending solar, biomass, or electrification, you first ask:

* How much coal do you use?
* How much electricity do you use?
* How much energy do you consume?
* How much does it cost?
* How much CO₂ do you emit?

Those answers are the **baseline**.

Everything else in the project compares against this baseline.

```
Current Factory
       │
       ▼
Baseline
       │
       ▼
Try Technologies
       │
       ▼
Compare with Baseline
```

# 2. energy_calculator.py

This file answers

> "How much energy does this factory actually need?"

Notice:

Energy ≠ Fuel

Coal is a fuel.

Electricity is energy.

Steam contains useful heat.

This module converts everything into common energy units.

---

Example

Suppose

```
Coal = 2000 kg/day
```

Coal has calorific value

```
24 MJ/kg
```

Energy produced

```
2000 × 24

=

48000 MJ/day
```

Now suppose

```
Electricity

4000 kWh/day
```

Convert to MJ

```
1 kWh

=

3.6 MJ
```

Therefore

```
4000 × 3.6

=

14400 MJ/day
```

Now

Total Energy

```
48000

+

14400

=

62400 MJ/day
```

This file performs calculations like these.

---

It may also calculate

* Useful Heat
* Thermal Energy
* Electrical Energy
* Total Energy Demand
* Energy Intensity (per unit production)

# Why separate Energy and Fuel?

This is a very common question.

Because they answer **different questions**.

### Energy Calculator

Asks

```
How much energy is required?
```

Example

```
60,000 MJ/day
```

---

### Fuel Calculator

Asks

```
Which fuel supplies that energy?
```

Example

```
Coal

Diesel

Electricity

Biomass
```

You can produce the **same energy** using different fuels.

Example

```
50,000 MJ/day

↓

Coal

OR

Biomass

OR

Electric Boiler
```

That's why they are separate modules.

# Example Walkthrough

Suppose the user enters:

| Parameter   | Value        |
| ----------- | ------------ |
| Industry    | Textile      |
| Coal        | 2000 kg/day  |
| Electricity | 4000 kWh/day |
| Production  | 10 tons/day  |

### Step 1 — `energy_calculator.py`

Calculates:

* Coal energy = 48,000 MJ/day
* Electricity energy = 14,400 MJ/day
* Total energy = 62,400 MJ/day

### Step 2 — `fuel_calculator.py`

Calculates:

* Coal cost = ₹16,000/day
* Electricity cost (using tariff) = ₹32,000/day *(example assuming ₹8/kWh)*
* Total daily energy cost = ₹48,000/day

### Step 3 — `baseline_engine.py`

Combines these into one structured result:

```json
{
  "total_energy_mj_day": 62400,
  "coal_cost_per_day": 16000,
  "electricity_cost_per_day": 32000,
  "total_cost_per_day": 48000
}
```

This object is then passed to the next modules (technology matching, scenario generation, optimization, etc.).

## Design advice

I would structure these files like this:

```
baseline/
│
├── baseline_engine.py      ← Orchestrates everything
├── energy_calculator.py    ← Energy calculations only
├── fuel_calculator.py      ← Fuel quantities & costs only
```

Keep **`baseline_engine.py`** almost free of formulas. Let it simply call the calculators and assemble the result. Put all calculation logic into `energy_calculator.py` and `fuel_calculator.py`. That separation makes the code easier to test, debug, and extend later.
