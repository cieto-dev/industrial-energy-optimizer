# MENTOR_NOTES.md

> **Purpose:** Maintain a record of mentor guidance, jury feedback, expert suggestions, and important observations received during the project.
>
> This document helps ensure valuable feedback is not lost and can be tracked until implemented.
>
> **Rule:** Record feedback exactly as received, as soon as possible after the session (same day if possible). Do not modify previous entries — add follow-up notes instead.
>
> **Status as of this update:** No feedback has been logged yet. This file was generated by the original documentation pass but never actually used. Fill in Entry #1 after your next mentor/jury interaction.

# STATUS LEGEND

| Status | Meaning |
|---------|---------|
| ⏳ Pending | Not yet implemented |
| 🟡 In Progress | Currently being addressed |
| ✅ Implemented | Successfully incorporated |
| ❌ Rejected | Not adopted (with justification) |

---

# HOW TO USE THIS FILE

1. Immediately after any mentor meeting, faculty review, or jury interaction, add a new numbered entry below using the template.
2. Fill in **Date**, **Source**, and **Feedback** verbatim — don't paraphrase in the moment, you can add interpretation in **Discussion**.
3. Convert each piece of feedback into a concrete **Action Required**, and where possible link it to a specific item in `FEATURE_BACKLOG.md`.
4. Once addressed, move the entry down to **IMPLEMENTED SUGGESTIONS** (or **REJECTED SUGGESTIONS** with a reason) and update its status here.
5. Skim the **REVIEW CHECKLIST** before every subsequent review so nothing raised earlier gets forgotten.
